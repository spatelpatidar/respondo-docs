One response shape. Every endpoint.

Respondo is a family of three standalone Ruby gems that give your controllers and services one expressive helper per situation, and one consistent response envelope, whether you speak JSON, GraphQL or gRPC.

render_ok(data: user, message: "User fetched")
render_not_found(message: "User not found")
render_unprocessable(message: "Validation failed", errors: user.errors)

Choose your gem

respondo

Consistent JSON responses for Rails controllers.

render_ok render_not_found

respondo-graphql

GraphQL-spec responses (data, errors, extensions) for everything outside your schema.

render_graphql_ok

respondo-grpc

A protobuf envelope with real gRPC status codes and structured errors.

render_grpc_ok

Install

Each gem is standalone: no dependency on the others, its own namespace and its own configuration. Install one, or all three.

# Gemfile
gem "respondo"          # JSON
gem "respondo-graphql"  # GraphQL
gem "respondo-grpc"     # gRPC
gem install respondo
gem install respondo-graphql
gem install respondo-grpc
# Gemfile
source "https://rubygems.pkg.github.com/spatelpatidar" do
  gem "respondo"
end
# one-time auth: a personal access token with read:packages
bundle config set --global rubygems.pkg.github.com YOUR_GITHUB_USERNAME:YOUR_TOKEN

Requires Ruby 2.7+. respondo and respondo-graphql hook into Rails through a Railtie, so there is nothing to include. respondo-grpc has no Rails dependency; it needs grpc and google-protobuf.

The idea

Three developers, three response shapes, and a frontend full of if (res.data || res.result || res.users). Respondo removes the argument: every response, success or error, comes from the same helper family and has the same shape, so clients never have to guess.
