respondo-graphql GraphQL · v0.2.0

Consistent GraphQL-spec responses for Rails controllers, in one line.

RubyGems GitHub Changelog Apache 2.0Ruby 2.7+

The GraphQL sibling of respondo. It is standalone: no dependency on respondo, its own namespace (RespondoGraphql), config and generator. Responses always use the GraphQL shape: data, errors, extensions.

When to use it

Your GraphQL schema already produces valid responses for queries and mutations. Use this gem for everything your controller answers outside the schema: authentication failures, rate limits, malformed requests, and REST-style endpoints that speak GraphQL-shaped JSON, so those look the same as the rest.

Install

# Gemfile
gem "respondo-graphql"
bundle install
rails generate respondo_graphql:install

The Railtie includes the helpers into ActionController::Base and ActionController::API. No include needed.

Usage

class GraphqlController < ApplicationController
  def show
    user = User.find_by(id: params[:id])
    return render_graphql_not_found(message: "User not found") unless user

    render_graphql_ok(data: { user: user }, message: "User fetched")
  end

  def create
    user = User.new(user_params)
    if user.save
      render_graphql_created(data: { user: user }, message: "Account created")
    else
      render_graphql_unprocessable(message: "Validation failed", errors: user.errors)
    end
  end
end

On failure data is null and errors[0] is always a summary carrying your message. Field-level errors follow, one entry per message.

Array and scalar payloads

GraphQL requires data to be a map, so an Array or scalar is wrapped as { "result": [...] }. Rename the wrapper with config.data_key.

Helpers

Same helpers, signatures and statuses as respondo, with a graphql_ infix: render_ok becomes render_graphql_ok.

204 and 205 have no body

HTTP forbids a body on 204 No Content and 205 Reset Content, so render_graphql_no_content and render_graphql_reset_content reach the client empty. Use render_graphql_ok when the client needs the message, or set config.always_ok = true.

1xx and 3xx helpers are left out on purpose: they are transport-level and have no meaning in a GraphQL response. The full list is in RespondoGraphql::ControllerHelpers::SUCCESS_HELPERS and ERROR_HELPERS.

Configuration

# config/initializers/respondo_graphql.rb  (written by the generator)
RespondoGraphql.configure do |config|
  config.default_success_message = "Success"
  config.default_error_message   = "An error occurred"
  config.include_request_id      = false   # adds request_id to extensions
  config.camelize_keys           = false   # created_at → createdAt
  config.always_ok               = false   # see below
  config.data_key                = :result # wrapper for Array / scalar data
  config.default_meta            = { api_version: "v1" }
  config.serializer              = ->(obj) { MySerializer.new(obj).as_json }
end

always_ok

Many GraphQL clients, Apollo among them, treat non-2xx responses as network failures. Set config.always_ok = true to send every response with HTTP 200 and let the errors array carry the failure. The default (false) keeps each helper's own status, such as 404 for render_graphql_not_found.

Using it with respondo

Both gems can live in one project. Every method this gem defines carries the render_graphql_ prefix, so nothing overlaps, and each gem keeps its own configuration.

class ReportsController < ApplicationController
  def show
    render_ok(data: @report)            # JSON    (respondo)
  end
end

class GraphqlController < ApplicationController
  def execute
    render_graphql_ok(data: @result)    # GraphQL (respondo-graphql)
  end
end

The gem checks whether respondo is loaded when Rails boots; there is no setting for it. To get render_ok as GraphQL in one specific controller of a project that also has respondo, opt in explicitly:

class GraphqlController < ApplicationController
  include RespondoGraphql::ShortHelpers   # explicit, per controller

  def execute
    render_ok(data: @result)              # = render_graphql_ok
  end
end
  • It is never included automatically next to respondo.
  • A warning is printed at class load if the JSON helpers are visible, so the switch is never silent.
  • Include it after the controller already has the JSON helpers. If you include Respondo::ControllerHelpers afterwards in the same class, render_ok is JSON again.
